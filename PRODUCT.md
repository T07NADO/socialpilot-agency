# Product

## Register

product

## Users

Two overlapping audiences sharing the same tool:

- **Solo freelancers** managing 3–10 client accounts. Working alone, often across multiple browser tabs, context-switching frequently. Time-poor. Need to move fast without making mistakes.
- **Small agency teams** (5–20 people) with distinct roles: account managers, copywriters, approvers. Collaboration happens inside the tool — someone writes, someone else reviews, someone schedules.

Both audiences are in "work mode" when using SocialPilot. This is not a tool they browse — it is a tool they operate. The primary job: get quality content approved and out the door for clients, on time, without friction.

## Product Purpose

SocialPilot is an agency-grade social media management tool focused on LinkedIn. It streamlines the full content lifecycle: AI-assisted composition, client approval workflows, scheduling, and auto-publishing. The product exists to remove the operational overhead between "a good idea for a client post" and "that post is live."

Success looks like: a solo freelancer can manage 8 clients' LinkedIn presence in 2 hours a week. A 10-person team can run approval workflows without a single Slack message about post status.

## Brand Personality

Calm, considered, precise.

The product is a quiet professional — it does not demand attention, it earns trust. It speaks plainly, acts predictably, and never makes the user feel like they're behind. The visual and interaction language should feel like a well-organised desk, not a command center.

## Anti-references

- Busy SaaS dashboards with metric cards stacked everywhere and colored gradients on everything
- Tools that make every action feel urgent or important
- Anything that looks like a generic "agency dashboard template" — identical card grids, sidebar navigation that is just a list of feature names, hero metrics with big numbers and sparklines
- Overwhelming information density that makes freelancers feel like they need an onboarding checklist to start working

## Design Principles

1. **One task at a time.** Each screen should have one clear primary action. Supporting information is present but secondary. Never compete for attention.
2. **Calm confidence.** The interface should feel like it has everything under control, even when queues are full. Avoid visual urgency unless something genuinely needs it.
3. **Progressive disclosure.** Show what is needed now. Details, settings, and edge cases live one level deeper — not on the primary surface.
4. **Invisible scale.** A freelancer with 3 clients and a team with 20 clients should both feel the tool is sized right for them. Layout and information density should adapt gracefully, not expose empty states or feel cramped.
5. **Precision over decoration.** Every visual element either communicates something or creates breathing room. Decoration for its own sake is noise.

## Accessibility & Inclusion

No specific WCAG requirements stated. Default to AA contrast ratios throughout. Ensure keyboard navigation works for all primary flows (compose, approve, schedule). Avoid motion that cannot be disabled.
